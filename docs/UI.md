# Rosa — UI spec (web/)

Read this before touching `web/`.

**Design system: "warm clay"** — warm cream/clay tokens, Inter (@fontsource-variable), light + dark themes (dark default), FIRING displays as **"Epic"**. All hexes confined to the two theme blocks in `styles.css`; tier colors only in the condition layer. Roomy and cozy, generous spacing, no decorative borders on cards. (`docs/rosa-conditions-color-system.md` is the older zine system — HISTORICAL, do not implement from it.)

Shell: **Today | Spots | Map | Profile**.
- **Today** — region chips + `planToday()` (chips from where you are + favorites + the ONE last-viewed spot; ≥5 spots per region; anchor leads; payloads load per region). Favorites are live page state (`useFavorites`), never a one-time read - the server sync lands after mount. Without a GPS fix, "where you are" is the spot an earlier fix ranked nearest (`rosa.home`), else the region you favorite most, and only then the last spot opened (2026-09-12).
- **Map** — full-bleed MapLibre + viewport-synced card carousel (cards are exactly the spots visible on the map, minus those under the sheet), screen-space clustering with tier-blend rings, focused-spot surf-pill dot, search overlaid on the live map, locate + rotating-north fabs. Lazy-loaded, excluded from PWA precache; OpenFreeMap vector basemaps by theme - keyless (attribution required).
- **Charts** — full-bleed swell map; its controls (layer tag, ramp, clock, play, ruler) sit in `.deck-card`, a card in the nav pill's own chrome floating just above the pill (2026-09-12 - they lay on the chart under a scrim before and got lost on busy frames). The outer `.charts-deck` still feeds `--sheet-h`.
- **Spot page** — one-row header, DayScrubber (date label over that day's 3 bars, one draggable track, leftmost = selected, live re-render on scrub, bars condense on scroll), rating card, hourly grid (wind in knots), TideSection from the real per-hour series, "Other nearby spots" strip.
- All date strips anchor to the spot's real today via `todayIn(tz)` and drop past days.

**Desktop (2026-09-08).** Above `DESK_MQ` (900px, `web/src/desk.ts`, mirrored by the DESKTOP block at the end of `styles.css`) the app is a full-width page, not the phone-in-a-frame it was: a sticky top bar (`components/DesktopBar.tsx` - brand, Today/Spots/Map/Charts as text links, a search field that opens `#/search`, the account avatar as the way into Profile) with a favorites ticker under it (tier dot, name, today's range, north to south; absent when there are no favorites), and the pill nav hidden. Surfline's site structure, Rosa's clothes. Nothing changes what a screen says, only where it sits: Today's card swipe becomes a grid and the coast chart shows every day across the row (`--days` is set on `.coast`); the spot page puts the hourly table straight under the day selector on the left (`.spot-hours` wraps it for this) and the cam, then the rating card, tide and sun, in a 420px right column, with the pinned header shrinking to a title line once you scroll; the Map stays full width with the card carousel in a band UNDER it, not over it (`isDesk()` turns off the sheet's bottom-strip exclusion from "visible"); Spots, Profile and Search sit in a 760px reading column; the About pages split in two, photo and title pinned on the left, text on the right. The DayScrubber's column width is measured from the DOM (`colW`), so the days can spread on a wide screen without breaking the scrub math. The document scrolls at every width. The splash and the sign-in screen swap to `public/splash_16-9.png` on wide landscape screens (`index.html` + `.signin-screen`).

**Routing and SEO (2026-09-12).** Path routes, not hash routes: `/`, `/spot/{id}`, `/map`, `/charts`, `/spots`, `/search`, `/settings`, `/about/{how|reading|terms|privacy|contact}` (`web/src/router.ts`: `parseRoute`, `pathFor`, `navigate`, `onRouteChange`). A hash route was one URL to a crawler, so 1,900 spot pages were indexed as a single page. Links are plain `<a href="/...">` (crawlable) and `interceptLinks()` turns same-origin clicks into pushState; nothing assigns `location.hash` any more. Old `#/...` links keep working: `adoptLegacyHash()` in `main.tsx` rewrites `/#/spot/x?ev=..` to `/spot/x?ev=..` before the router reads it (push notifications, shares, the old-origin favorites hand-over `?import=`). Every screen sets its own `<head>` (`head.ts` `setHead`; `seo.ts` `headFor` per route; `SpotPage` calls `spotHead` with the published name, town, region and coordinates - title, description, canonical, Open Graph, `Place` JSON-LD). `spots`, `search` and `settings` are `noindex`. **The build prerenders a shell per path** (`web/scripts/prerender.mjs`, after `vite build`): `dist/spot/{id}.html` for every spot in the published index (fetched from `VITE_DATA_BASE`, local `public/data` as fallback) with an `h1`, the place line, a forecast paragraph and its 8 nearest spots as links; `dist/about/*.html` with the real About text (`preact-render-to-string` through `src/prerender-entry.tsx`, `vite build --ssr`); one shell per other screen; `sitemap.xml` (root, map, charts, about, every spot). `index.html` carries the same for the root plus a static block inside `#app`; `main.tsx` empties `#app` before rendering (no hydration - the block is for crawlers and JS-off). `vercel-output.json` serves the files: `handle: filesystem`, then `/spot/x` -> `/spot/x.html` (`check: true`, so a spot added after the last web build falls through), then everything else -> `index.html` **with status 404** - no soft-404s, so **deploy the web app after adding spots** or their pages answer 404 until the next `npm run deploy`. `public/robots.txt` allows all but `/data/` and the three personal screens and names the sitemap. Share image `public/og.jpg` (1200x630, from the splash photo).

**DESIGN RULE: swell events surface ONLY as push notifications.** The forecast itself is the in-app surface. Do not rebuild event banners, cards, or alert strips — they were built and killed on review.

**Push.** One swell = ONE notification: same region + peaks ≤12 h + dirs ≤45° cluster into a single push named for the best favorited spot "+N more"; sent-state carries ±1-day peak-drift tolerance; browser tag is a 2nd dedup layer. Notification tap deep-links `/spot/{id}?ev=YYYY-MM-DD` (`notify.py` still sends the older `#/spot/...` form; the router adopts it, see Routing below). Opt-out must be clear and failures surfaced, never silent. iOS needs A2HS + a user gesture.

**Feedback ask is two steps:** "Surfed X?" ✓/✗ first, thumbs only on yes. Selection never crosses regions (the device sends its nearest spot id, never coordinates). Asked at most once a week, only about a GOOD-or-better day, and only for the favorite spot closest to the user's current location (2026-08-20).

**Period display ≠ scoring** — the swell readouts show the PEAK period while `period_score` and the shoaling march run on the mean. Deliberate; see `docs/ALGORITHM.md`. Disclosed at `/about/reading`.

**Account and favorites (2026-09-07).** Saving a spot needs a Google account; the forecast itself never does. `web/src/favorites.ts` keeps `rosa.favorites` as this device's CACHE of the signed-in user's list; the truth is `deploy/user-api` (Cloudflare Worker + D1, `docs/../deploy/user-api/README.md`), reached only through `web/src/account.ts` (`GET /me`, `PUT /me/favorites`; debounced 800 ms after a toggle, retried on launch and reconnect via `rosa.favorites.dirty`). Signed out, a star tap opens the **sign-in screen** (`components/SignInScreen.tsx`) instead of saving, and the tapped spot is saved the instant sign-in lands. The screen is the SPLASH, continued: same photo, scrim, glow, mark and wordmark (values copied into `.signin-*` in `styles.css`, keep them in step with `index.html`), one z-index below `#splash`, so a signed-out launch lifts the splash straight onto "Save your spots" + Google's button + **Not now**. Not now holds for the launch (`sessionStorage`); the star asks again. Google's button (Identity Services, popup mode, English) is the only third-party script and is injected on first need, never bundled. Its failures are named separately (2026-09-09): Google unreachable says so, no connection says "You're offline", and our own user API not answering says "Rosa couldn't be reached" - before that a dead user API and a dead device connection both blamed Google. Since 2026-09-11 two more are split out of "Google": Google's script failing to load on an online device says a privacy or ad-blocking extension may be blocking it (the Disconnect extension did exactly this and the old text told the user to check their connection), and GIS's `popup_failed_to_open` says the browser blocked the sign-in window. A script timeout still reads "Google didn't answer". Profile > **Account** card (first card): signed out = one line + "Sign in with Google" (same screen); signed in = avatar, name, email, Sign out (revokes every device's session), Delete account (confirm, deletes the row). Sign-out empties the local favorites - they are the account's and come back on the next sign-in. Pages take favorites through `useFavorites()` so a sign-in merge or another device's change re-renders them.

**Old origin (`rosa-rust.vercel.app`).** Navigations 308 to rosa.surf; every other request is served, so apps installed there before the move can still update - and what they update to is `components/MovedScreen.tsx` ("Rosa has moved", Open rosa.surf), never the forecast. Keep it that way: the forecast runs only on rosa.surf (2026-09-07).

**Install from Samsung Internet goes through Chrome (2026-09-10).** Samsung Internet offers an install, but Samsung's server wraps the app with an old Android target and Google Play Protect blocks it on Android 14+ as "built for an older version of Android" (SamsungInternet/support#123, open since 2026-04; every PWA, not Rosa's manifest). So on Samsung Internet for Android the install sheet and Profile's Install row (`web/src/install.ts`, offer `"chrome"`) skip Samsung's install and say "Open in Chrome": an `intent://` link with `package=com.android.chrome` that reopens rosa.surf in Chrome on Home, where Chrome's own install is clean; no Chrome on the phone falls back to Chrome's Play Store page. Drop it once Samsung fixes the issue.

**Embed widget (2026-09-14).** `web/public/widget/index.html` is a single static page for surf businesses to iframe: one spot, one day at a time, the spot page's own hour grid at 06:00 / 12:00 / 18:00 (surf range + swell height, swell arrow/period/cardinal, wind box, kJ/hPa), a satellite cover with a black "rosa.surf" sticker top-left, the name/region/pill line and air/water/wetsuit under it, the date centred, dots under the grid. Swipe (or drag) changes the day; any click opens `/spot/{id}` in a new window - the only two actions. Query: `?spot=<id>&theme=dark|light&units=metric|imperial` (imperial = ft, °F, mph). Vanilla HTML+JS, no bundle: it reads `VITE_DATA_BASE` directly, Esri tiles as the app's featured card, Inter from Google Fonts. Type and grid metrics size off the CARD's width (`@container`, 16px at 420px down to 11px), max-width 420px. `vercel-output.json` excludes `/widget/` from the site-wide `X-Frame-Options: DENY` and gives it `frame-ancestors *`; `vite.config.ts` keeps it out of the service worker's precache and navigation fallback (an installed app's worker would otherwise answer a third-party frame with the shell). The embed tag comes from the `/rosa-widget` skill (`~/.claude/skills/rosa-widget`): share link + theme + units -> iframe, 100% wide, 500px tall.

**Contact Us** (`/about/contact`, an `AboutDoc` rendered by `AboutPage.tsx` like the other static pages, linked from Profile > About Rosa): one text block + Send. POSTs to the push API's `/api/contact` (`deploy/push-api/api/contact.js`), which stores every message as a private blob under `contact/` and emails it via Resend (`RESEND_API_KEY`, `CONTACT_TO`); a failed POST falls back to a `mailto:` link carrying the text. Added 2026-09-02.

**Report nudge (2026-09-09).** A full-screen note (`web/src/components/ReportNudge.tsx`, schedule in `web/src/nudge.ts`) telling a new user the spot page carries a Report an issue button and that a person reads every report - "Know a spot better than we do?", X top right, one blue OK at the bottom, both only close it. Shown on a device's first launch and on every sign-in, then once a week for four more weeks (`rosa.nudge.report` in localStorage: `{started, shown, last}`; a sign-in restarts the run, a sign-in within 10 minutes of a showing does not re-show). Painted `--body-bg` like the report page, at z 59 - under the install sheet and the sign-in screen, so a fresh install answers those first and finds this waiting. Layout is the Figma file `Rosa`, page `designs`: **mobile** (node 1:21) is the full-screen page - everything centred in a 402px column, 40px padding, 20px bold title, 16px body at 1.6 with the line broken after "Check your favorites." and "A person reads every one." as its own paragraph, and the OK button `--accent` (#11B7F2, the frame's Brand blue secondary), radius 16, 15px tall. **Desktop** (node 1:42, above the 900px `DESK_MQ`) turns the same block into a 582px modal card over the app: 80px padding, radius 16, the mock's 6%-black shadow, on a 60% `--body-bg` scrim (`color-mix`, so it dims in whichever theme is on). Dark adds a `--border` hairline the mock does not have, because a 6%-black shadow is invisible on the dark ground.

**Report** (per spot, `components/ReportSheet.tsx`, CTA in `SpotPage.tsx`'s `.day-title`): a FULL-SCREEN page, not a sheet - `--background` is 11% white over a photographic backdrop, so an overlay let the forecast bleed through and was unreadable; the report paints `--body-bg`, the one opaque token. Reasons are CHECKBOXES (a pin can be wrong and the wind off at once), plus "Something else" which makes the note required. Six fixed reasons (wrong location, wrong name, forecast too high, too low, wind wrong, camera offline) plus an optional note. Mailed to the maintainer tagged `[report]` with the spot's name, id and coordinates; **nothing is applied automatically, every report is read by a human first.** Shares the Contact Us transport in `web/src/contact.ts`. Added 2026-09-03.

Data-point glossary lives in `AboutPage.tsx` → `ReadingTheForecast` (`/about/reading`) — **keep in sync when a displayed field changes.**
