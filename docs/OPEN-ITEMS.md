**Read this before writing "grade more frames" into any item (2026-08-04).** Eye frames are
available in **Israel only** — that is where the user is. Remote grading needs a cam, and only
**14 of 199 spots have one**: japan 5, portugal 3, california 2, costa-rica 2, hawaii 1,
israel 1. sri-lanka (32), philippines (16), nicaragua (15) and most of portugal/costa-rica have
neither, and are **buoy-only, permanently**. `docs/CALIBRATION.md` already settles this —
"ground truth for the whole world cannot come from human eyes… primary global validation is
buoy-only" — so an item demanding worldwide eye frames is asking for something that cannot be
supplied. Where eyes/cams genuinely are the only instrument (rideability, a wind coefficient),
say so and scope the item to the spots that can actually deliver it.

8. **Cams rot on a timer.** A 24/7 stream mints a new video id on every restart, so a pinned id dies within about a day on some channels (santa-teresa died twice in two days). `/embed/live_stream?channel=` is NOT the escape — YouTube deprecated it and it returns Error 153, verified in a browser 2026-08-03. **Detection is already automated** — `deploy/oracle/cam-watch.sh` runs weekly (`40 5 * * 1`) and pushes ONE admin alert listing dead cams, which are auto-repairable by title match, and which need a human. It ran 2026-08-03 05:40Z and called all five correctly. It deliberately does not `--apply`: the VM has a read-only deploy key, so a dirty `data/spots` would break the next `git pull --ff-only` and freeze the box on local code. **Repair is the human half**, run from a clone that can push: `YOUTUBE_API_KEY=$GOOGLE_MAPS_API_KEY python3 tools/cam-scan/scan.py verify --resolve --apply`. **Do not use the channel `/live` page as a shortcut**: it served a different beach for aoshima where the API found the correct title match, which is the whole reason the tool is API-only. Every assigned cam is live, verified on the CDN 2026-08-04 (`costa-caparica` stays at one angle — its dead Santo António feed was removed rather than re-pointed, because its channel's only unmatched live stream is Marina de Portimão, a different place; user-confirmed 2026-08-04, do not re-open). Still unsolved: a dead embed shows YouTube's raw "This live stream recording is not available" rather than an honest offline state, and the weekly cadence means a cam can be dark for up to a week.
9. **A failed `archive` kills the whole cycle.** `publish.sh` marks it ESSENTIAL and leaves it unguarded under `set -e`, so the run dies at step 1 and `run --all` never executes — that is how 2026-08-03's cam fixes sat undeployed for 12 h behind an Open-Meteo **daily**-quota 429 (`"try again tomorrow"`, per-IP, resets 00:00Z). The stated rationale — the buoy lead-time archive is a clock that can't be back-filled — justifies alerting on archive, but not aborting: the archive hour is lost either way, so hard-failing turns one unrecoverable loss into two. Unresolved: make archive non-fatal (`|| on_fail`-and-continue) and let the forecast refresh proceed, or keep the coupling deliberately. Also unmeasured: what actually consumed the daily quota, and whether 4 cycles/day × 199 spots sits near the ceiling in normal operation.
