# CLAUDE.md - Rosa

Rosa is a **worldwide, mobile-first PWA surf forecast app**: free, lean, fast, shareable. A daily-use tool replacing Surfline for dedicated surfers, minus the bloat and paywall. Full context: `docs/rosa-surfline-teardown.md` (competitor analysis + data schema findings) and `docs/rosa-build-plan.md` (product plan). Read both once before major architectural work; this file alone is enough for routine tasks.

## Non-negotiable principles
1. Every screen answers "should I surf, when, where?" - cut anything that doesn't.
2. **Precompute everything, serve static.** Pipeline runs on schedule → per-spot JSON + map frames on CDN. No request-time forecast backend, ever. This is what keeps the app free.
3. Always display model name, run timestamp, and confidence. Rating formula is public ("why this rating" in-app) - transparency vs. Surfline's black box is a core differentiator.
4. Mobile-first, dark-first, < 2 s first load on 4G, forecast readable in a 20-second pre-dawn check. Installable PWA, offline-cache last forecast.
5. Every forecast state and swell animation has a shareable URL + auto share card.

## Legal red lines
- NEVER fetch, proxy, or reproduce Surfline API output, spot guide text, cams, or their spot database. The teardown is for structural understanding only.
- NEVER scrape third-party camera streams (any provider, not just Surfline). Cams enter Rosa only as officially embeddable/permitted public streams (per-spot `cam_url`, v0.3+) or via partnerships.
- ISRAMAR (isramar.ocean.org.il) data/imagery is all-rights-reserved: use only for manual validation during calibration; pursue partnership before any integration.
- Open-Meteo: free tier is non-commercial, attribution required - fine for a free app, add attribution in footer; re-verify terms before public launch.
- CMEMS/Copernicus: free with registration; attribution required.
- Open data we build on freely: NOAA (WW3/GFS/OISST/NDBC/CO-OPS), ECMWF open data, EOT20 tides (CC-BY), GEBCO, OSM.

## Algorithm specs (implement exactly, unit-test all)
- **Wind classification**: θ = smallest angle between wind *source* direction and `offshore_direction` (shore-normal pointing FROM land TO sea... convention: `offshore_direction` = direction offshore wind comes FROM, e.g. Israel coast faces W → offshore wind is E → offshore_direction: 90). θ ≤ 45° → Offshore; 45-135° → Cross-shore; > 135° → Onshore.
- **Swell energy in window**: for each swell partition with direction inside `swell_window`: E += H² × T. Partitions outside window contribute 0 to score but still display.
- **Rating v1 (0-100)**: size 0-40 (ramp of transformed height vs. spot `ideal.size_m`, peak inside range, taper above), period 0-20 (linear 6 s → 0 pts to 14 s → 20 pts, dominant in-window partition), wind 0-40 (offshore ≤ 15 kph = 40; scale down with speed and with angle; onshore ≥ 25 kph = 0). **Wind gate** (calibration fix #1; denominator 30→60 in row 2): wind points scale by `min(1, (size_pts + period_pts)/60)` - offshore wind polishes waves that exist, it never creates rating on its own. Day-strip `rating_max` uses daylight hours only (dawn-dusk via astral). Buckets: 0-9 FLAT, 10-29 POOR, 30-49 FAIR, 50-69 GOOD, 70+ FIRING.
- **Breaker height v2 - hybrid physics (Stage 2B, DONE 2026-07-22; truth: `docs/rosa-stage2-plan.md` + `physics.py`/`transform.py`)**: per in-window partition, march the spot's committed depth profile (`data/spots/derived/bathy/{id}.json`, 199 profiles - one per spot) applying dispersion → shoaling `Ks` → Snell refraction `Kr` → depth-limited breaking at γ=0.78·d (tide added to breaking depth), **and where the profile runs out before the wave breaks - which is 97-100% of published hours - closing the last stretch with the Komar & Gaughan (1972) breaker index `Hb = 0.39 g^0.2 (T H0'^2)^0.4` (`breaker_height_komar_gaughan`, 2026-08-02)**, then multiply by `period_rideability` (the grounded reframing of q(T): power-based, capped at 1.0, attenuates only - naive physics alone over-calls short-period Med windswell ~3×); combine partitions RMS. **`period_rideability` keys on the partition's PEAK period (`rideability_period()`, mean only as a no-Tp fallback) - Stage 2E, 2026-07-30, the first knob moved since calibration row 2.** Keying it on the mean under-called real Med swell 1.6-2x at three graded frames (Hilton x2 + Poleg); it also matched what `energy_period`/the kJ column already did. **`RIDEABILITY_EXP` 1.4 → 2.2 on 2026-08-02**, refitted because 1.4 had been fitted on top of the truncated march and was partly absorbing it. Because rideability saturates at its 1.0 cap above ~10 s the exponent is in practice an **Israel/Portugal knob** (Israel x1.39→x1.06 across 1.4→2.2, Costa Rica/Nicaragua/California barely stir) while the breaker-index closure is a **long-period-region correction** - they separate cleanly, and 2.2 is what leaves the calibrated region where its graded frames put it. NOTE the dispersion/shoaling march and `period_score` still consume the MEAN period; only the rideability factor keys on Tp. **`peak_period` is only published by `gwam`** - `best_match` resolves to `meteofrance_wave`, which serves none, so before 2026-08-02 Tp existed only in Israel/Portugal (18.9%/15.7% of partitions, 0.0% everywhere else) and the 2E fix was reaching two regions; `gwam` now rides the same marine request as a **Tp-only** source (`fetch.TP_MODEL`, ~7.3-day coverage, secondary/tertiary partitions still have none because the API has no such variable). **Spread-aware exposure (2026-07-29, replaces the pencil-beam window)**: a partition is not one bearing - its energy fans over ±20-35° (`spectral.parametric_spread_deg`, CDIP-tuned), so `spread_exposure()` integrates the soft window (flat 1.0 inside `swell_window`, cosine taper to 0 over a 25° shoulder, `EXPOSURE_SHOULDER_DEG`) over that fan and returns the ENERGY fraction that reaches the spot (amplitude = sqrt). The incidence fed to refraction is `arriving_direction()` - the window edge the energy comes in over, not the fan's mean - and is capped at `GRAZING_INCIDENCE_DEG` (85°) so a window reaching past the shore normal (wrapping points, bay mouths) is honoured rather than cancelled. **Invariant: a metre offshore can never read as ~0 at the spot** - that was the bug (Pipeline 0.0-0.1 m vs Surfline 0.3-0.6; CALIBRATION.md 2026-07-29). Energy/kJ uses the same exposure as the height, so a row can't show surf beside 0 kJ. `height_coeff` survives only as a small per-spot residual. The old `q(T) = clamp((T/10)^1.4, 0.3, 1.2)` path (`PERIOD_EXP` in transform.py) remains the **no-profile fallback only**. Display as range h±20%, snapped to 0.1 m, widened to a real ≥0.1 m spread ("0.1-0.1" isn't a range). Tune γ / rideability exponent / residual coeff from the calibration log + Stage-0 scorecard only (Stage 2E ran 2026-07-30: the period KEY moved, γ and the residual coeff did NOT). Full spectral retirement of the rideability proxy is Stage 3.
- **Human phrase**: map h_break midpoint → [<0.3 shin-high, 0.3-0.5 knee, 0.5-0.8 waist, 0.8-1.2 chest, 1.2-1.5 head-high, 1.5-2 overhead, 2-3 well overhead, >3 double-overhead+]. Wetsuit from SST (industry-standard bands, adopted 2026-07-19): >24° rashguard, 19-24 spring/2 mm, 17-19 3/2, 14-17 4/3, 12-14 5/4+boots, 9-12 5/4 hooded+gloves, <9 6/5 hooded.
- **Swell-event detection** (feeds alerts + swell stories): a contiguous ≥ 12 h window where in-window energy ≥ 2× trailing 48 h median and rating ≥ GOOD at peak. Emit {start, peak, end, peak_height, direction}.
- **Tides** (Stage 2D, 2026-07-22 - approach changed): Open-Meteo Marine `sea_level_height_msl` (MeteoFrance SMOC, ~8 km hourly) fetched alongside the waves - **total** water level (astronomical tide + surge), not just astronomical. Fed into the nearshore transform's breaking depth (`d_break = profile_depth + tide`) and published as a per-hour series (replaces the web's mock M2 sine). Supersedes the original EOT20/pyTMD-per-spot plan: Open-Meteo gives the same global coverage with no multi-GB download and no heavy dep, behind the existing fetch interface (swap to EOT20 later if tide independence is wanted, same as the wave-model migration). Med spots micro-tidal (~0.15 m, sparkline only); macro-tidal spots (Costa Rica ~1.5-2 m) genuinely move the forecast.
- **Sun**: `astral` lib; show first light/sunrise/sunset/last light.

## Spot database
`data/spots/*.yaml` - one file per region: **199 spots - israel.yaml (42), costa-rica.yaml (25), sri-lanka.yaml (32), japan.yaml (24), portugal.yaml (42), nicaragua.yaml (15), philippines.yaml (16), california.yaml (2), hawaii.yaml (1)** (JP/PT/NI/PH added 2026-07-23), plus committed derived depth profiles in `data/spots/derived/bathy/` - one per spot, all 199, no gaps and no orphans (`test_committed_bathy_profiles_match_their_spots` enforces both). **Keep these counts current: any spot added/removed updates this line AND `test_loads_israel_seed`'s assertion - no approval needed.** **`shore_normal` aims the depth ray the physics marches, `offshore_bearing` aims the sample point, `offshore_direction` is where OFFSHORE WIND blows from - all three describe the same coastline and are guard-tested against each other** (a spot whose ray disagreed by 102° marched swell up a hillside and read 0.0-0.1 m all day; 2026-07-29). **A spot's `lat`/`lon` is the ONLY place its location is written down** - `offshore_point` is derived, never stored (aim it with pin-relative `offshore_km` + `offshore_bearing`; the absolute `offshore_point:` field was removed 2026-07-26 and now raises), and a bathy profile records the `origin` pin it was cast from so a stale one is detectable instead of silently feeding wrong depths into `h_break`. Bathymetry follows the pin: move a spot and its profile is stale, so delete it and re-cut (`rosa-pipeline bathy --spot <id>`); remove a spot and its profile is deleted. Never leave an unused profile behind. **`swell_window` can now be DERIVED instead of guessed: `rosa-pipeline horizon --spot <id>` (horizon.py) fans rays over 360° from the pin off the same GEBCO source and returns the contiguous open-ocean arc containing the shore normal, clipped to ±90°.** It reports and never applies - same rule as the cam tool. Two thresholds, not a sign test: a submerged bar reading 0 to +2 m in GEBCO will otherwise be read as a headland and carve a false notch through open ocean (`HORIZON_LAND_M` 3.0 m of land, `HORIZON_DEEP_M` -50 m of sea, in that order; stable for any land threshold 2-5 m). **Only `santa-teresa` has been derived so far ([190,310] regional default → [160,290], 2026-08-02, CALIBRATION.md) - the other 198 still carry hand-set regional defaults tagged "approx - TODO verify".** Geocoding provider (verified 2026-07-23): Google **legacy** Places textsearch - the project's key is restricted to the legacy APIs, so `tools/spot-verify/geocode.py` tries Places API (New) and falls back automatically; Geocoding/Elevation/Static Maps APIs are NOT enabled on the project. Nominatim/Photon benchmarked far worse on surf POIs (gross >100 km misses) - don't switch without re-benchmarking. Google returns the named POI (town/lodge/mosque), not the peak: use it to seed/flag, never to overwrite sat- or user-verified pins. Coordinate authority ladder: user-verified > sat-verified (`tools/spot-verify/` ESRI-crosshair loop, `docs/spot-mapping-approach.md`) > OSM features (© OpenStreetMap contributors, ODbL) > google-geocoded > approximation - each spot tagged with its source. LESSON (2026-07-19): OSM beach polygons ≠ surf spots - Herzliya was mismapped until user-verified: Sidna Ali 32.196 > Gazebbo 32.176 > Zvulun 32.173 (north Herzliya Pituah, NOT the marina) > Acadia 32.166 (Dan Accadia cape) > The Marina 32.164 (cove N of harbor mouth) > Dromi 32.158 (S of marina). Local knowledge always wins; treat every user pin correction as authoritative and tag it user-verified.). This DB is the long-term moat: design every addition to be community-contributable. Derive `offshore_direction` from OSM coastline geometry when adding regions in bulk. Never import competitor spot data.

## Conventions
- Python: uv, ruff, pytest; type hints everywhere; pipeline stages pure functions (input → output, no hidden state) so fixtures test everything offline.
- TS strict; Preact if bundle size threatened; no UI framework bloat; PWA via vite-plugin-pwa.
- Fixtures: `pipeline/tests/fixtures/` holds captured Open-Meteo responses so tests never need network.
- Commits small, conventional (feat:/fix:/data:). Data outputs are build artifacts - never committed to main repo.
